## The theme of this round

Safety held. No path was found that makes the validators sign a forged, mis-scaled or mis-routed transfer. The Solana gate, hash parity, decimals and H-4 corroboration all checked sound.

The failures are in **liveness**: one cheap public action, or one shared credential, stops a whole source chain permanently. That happens because scanners treat a *permanent* store rejection as a *transient* error and retry the same range forever.

Two more items are about **where refunds and governance actually land**. These are not exploits; the problem is that the designed recovery path doesn't reach the user.

## HIGH

### H7-1 — Every container in the generated compose stack can read every signing key (live on mesh11)
`scripts/bridge-from-json.sh:850-935`, `emit_signer` at `:210`; `docker/testnet-mesh11/docker-compose.yml:54,66,77,85,93,115`.

- **What happens:** `emit_signer` writes `private_key` inline into `configs/validator-*.toml`, `keeper-*.toml` and `price-keeper.toml`, all mode 0644. All services, **graphql-api included**, mount the whole `./configs`.
- **Impact:** mesh11 is 2-of-2. A file read in the internet-facing API yields a full validator quorum plus the price-keeper key, which is still the gate owner.
- **Status:** an incomplete T-5 fix. c23dd20 scoped `keys/` per service but not `configs/`. The files are gitignored, so nothing leaked through git.
- **Fix:** mount only each service's own TOML, and give graphql-api `chains.json` only. Prefer `private_key_env` or a keystore, as `docker/production` does.
- **FIXED 2026-10-02** (code; the live mesh11 containers still need recreating):
  - `bridge-from-json.sh --compose`: every service mounts only its own TOML, plus its own staged keystore/password file under `keys/<service>-*` and its own signer env vars. graphql-api mounts `chains.json` only.
  - New bridge-config field `profile`: `"dev"` (default) allows inline keys with a warning; `"production"` refuses any inline `private_key` / `keystore_password` at generation.
  - `private_key_env` now works under compose. It is passed through from `.env` to that one service, and never generated.
  - Root `docker-compose.yml` (dev, anvil keys) and `docker/production/api` mount single files too.
  - Signer env var names are validated as identifiers and cannot shadow `SIG_STORE_*`, `RPC_*` or `POSTGRES_PASSWORD`.
  - Verified: dev, production (env + keystore), Solana-relayer and inline-refused stacks generated, and `docker compose config` passes. Regenerating mesh11 changed only its mounts.

### H7-2 — One public `Gate.send` with >32 KiB `autoParams` permanently halts the indexer and every validator on that source chain
`Gate.sol:1063-1128` (no length bound), `bridge-db/src/lib.rs:94,119` (`MAX_AUTO_PARAMS_BYTES = 32 KiB`), `indexer/src/main.rs:369`, `validator/src/main.rs:852` → `batch_failed`.

- **What happens:**
  1. The store rejects the row with a 4xx, every time.
  2. The indexer's DB cursor never passes that block.
  3. Every validator replays the window forever.
- **Impact:** nothing later from that chain is signed. The attacker's own deposit can never be refunded.
- **Status:** a regression of the round-5 length bounds. CONFIRMED for the indexer by test; for the validator by code reading.
- **Fix:** cap `autoParams.length` in `Gate.send` at or below the store bound. Treat a deterministic store rejection of a gate-emitted `Sent` as quarantine-and-advance, never retry.

### H7-3 — The M-2 signer cap is first-come-first-served: 64 junk signers freeze a transfer and wedge every validator's scan loop
`bridge-db/src/lib.rs:494-513`, `bridge-core/src/store.rs:244-253`, `validator/src/main.rs:852` → `:662-671`.

- **Who can do it:** any holder of the shared Sign token. That is every validator and every solana-relayer, because sig-store accepts only one `validator_token`.
- **What happens:**
  1. The attacker posts 64 junk transfer signatures, 64 junk cancel attestations and 64 junk refund attestations for an id. They can do this before the transfer reaches its confirmation depth.
  2. Real validators then get `TooManySignatures` in all three domains, so the transfer is frozen.
  3. That error fails `handle_log`'s batch, so the source-chain cursor stops for the whole fleet.
- **Status:** CONFIRMED.
- **Fix:**
  - sig-store must know the validator set and refuse non-members rather than capping strangers.
  - It must never refuse a configured validator.
  - Issue one token per validator.

### H7-4 — A refunded swap-and-bridge pays the source SwapRouter, not the user
`SwapRouter.sol:372` → `Gate.sol:1115` (`sentBy = msg.sender`) → `Gate.sol:1364-1389`.

- **What happens:**
  - The router is the gate's `sentBy`. Every cancelled xswap therefore refunds into `routerA`, which records no user and has no forwarding.
  - The stable is not counted in `owedStable`, and `rescue` refuses it.
  - The only exit is the owner's manual 48 h stable rescue, while the UI shows "refunded".
  - `SwapRouter.sol:423` assumes the opposite ("the source chain separately refunds the original sender").
- **Status:** CONFIRMED (`test_R7_1_XSwapRefundLandsInRouterNotUser`).
- **Fix:** have the router record `refundTo[id] = msg.sender` and add a permissionless claim-refund-and-forward, or let `Gate.send` take an explicit refund address bound into `sentBy`.

### H7-5 — H-6 is incomplete: junk rows starve every later refund candidate
`validator/src/refund.rs:505-527`, `bridge-db/src/lib.rs:1482-1528`.

- **What happens:**
  - The walk restarts at offset 0 each tick and stops at 10,000 rows ordered by `created_at`.
  - About 10k Sign-token junk rows never leave the queue, because no chain ever emits them.
  - Every genuine stuck transfer created after them is never examined.
  - Each junk row also costs 10–30 RPC calls per tick.
- **Status:** CONFIRMED.
- **Fix:**
  - Only sweep indexer-observed rows that already have threshold signatures.
  - Use a persisted keyset cursor.
  - Keep a "not sent" memo.

### H7-6 — One Solana `send` with `auto: Some(..)` halts every validator's Solana source scanner (latent: mesh11 is EVM-only)
`solana-relayer/src/source.rs:671` (always `auto_params: "0x"`), `:686`, `:494`.

- **What happens:**
  1. The id is computed with the auto payload, but the record is stored without it.
  2. The store recomputes the id and returns `IdMismatch` (4xx).
  3. `tick` returns before `cursor.save`, so the scanner re-reads the same transaction forever.
- **Status:** the round-6 quarantine does not cover store rejections. CONFIRMED.
- **Fix:** ABI-encode `sent.auto` into `auto_params`, and quarantine any permanent 4xx.

## MEDIUM

### M7-1 — The post-seal governance timelock gives no usable veto against a stolen owner key
`Gate.sol:1018` (`setGuardian` is instant), `:384/:785` (`GovernanceScheduled` emits only a hash).

- **What happens:**
  - The owner schedules an action and calls `setGuardian(0)` in the same block, so cancel is gone.
  - The action hash hides which corridor or token is queued. For `setBridgeDecimals` the token can be a CREATE2 address with no code yet.
  - The PoC drains a sealed 1M USDC vault after 48 h.
  - Only validator-side **locally pinned** tokens stop it.
- **Status:** CONFIRMED.
- **Fix:**
  - Make guardian changes a timelocked action.
  - Emit decoded parameters on schedule.
  - Require the token to have code when it is scheduled.

### M7-2 — M-14 is incomplete: the stable rescue is capped by amount, not by which funds
`SwapRouter.sol:541-551, 594-599`.

- **What happens:**
  - The owner baits the rescue's `freeAtSchedule` with their own transfer, finalizes the bait out, and then sweeps a victim's stable that landed after the notice.
  - The victim's `finalize` defers forever, and the Gate shows executed, so no refund is possible.
  - The 48 h natspec assumes the keeper finalizes. It never calls `finalize`; only the user's browser does.
- **Status:** CONFIRMED.
- **Fix:** account per delivered id; add a keeper finalize loop.

### M7-3 — Oracle updates are sandwichable; pool fee is 0 by default
`SwapPool.sol:338-364, 453-494`.

- **What happens:**
  - Trades execute at exactly the oracle price.
  - The price-keeper's capped steps are predictable without watching the mempool.
  - Profit is up to 10% of the attacker's capital per update, taken from reserves.
- **Status:** CONFIRMED; the PoC makes +20k on 200k.
- **Fix:** a fee at least as large as the per-update move, a private relay, or commit-then-apply-next-block.

### M7-4 — Price-keeper steps from a single-RPC read of the on-chain price
`price-keeper/src/main.rs:235-265`, shared `plan` in `swap-math/refresh.rs`.

- **What happens:** a lying endpoint makes the oracle key sign moves of up to 10% per interval away from target. This is the H-4 class, unaddressed here.
- **Status:** logic CONFIRMED; practical exploitation PLAUSIBLE.
- **Fix:** compare-and-set `setPrice(token, expectedOld, new)`, or require several endpoints to agree.

### M7-5 — The API rate limiter is one global bucket in every shipped topology
`graphql-api/src/main.rs:205-209` with `docker/nginx.conf.template:62-67`.

- **What happens:**
  - The limiter is keyed on the TCP peer, which is always nginx.
  - About 30 rps from one client puts every user on 429.
  - The quotes and gate context then go null, the H-2 checks fail closed, and nobody can bridge.
- **Fix:** forward the client IP, trusted only from the proxy CIDR, or use `limit_req` in nginx.

### M7-6 — `swapPool` / `pools` bypass the upstream meter and cache
`graphql-api/src/swap.rs:521-578, 730-756`.

- **What happens:** 50 aliases produce 50 or more uncached upstream calls. `Token.bridgeDecimals` has no complexity cost, and unregistered results are not cached.
- **Status:** CONFIRMED.
- **Fix:** route these through `upstream.cached`, and give `bridgeDecimals` a cost.

### M7-7 — The frontend swap-and-bridge flow can submit with zero or mis-scaled slippage floors
`frontend/src/components/BridgeView.tsx:505, 513-516, 739-770`; `SwapView.tsx` debounce.

- **What happens:**
  - The button stays enabled with null or stale quotes, which signs `finalMinOut = 0` into the id.
  - Leg 2 is quoted in the source stable's decimals, but the router swaps destination-local units. When the stable's decimals differ per chain, the floor is off by 10^Δ.
- **Fix:** gate the button on quotes keyed to the current amount, and rescale leg 2 through the wire scale.

### M7-8 — A stuck or low-head serving endpoint silently stops a validator
`validator/src/main.rs:434-449, 706-708`, `provider.rs` (`with_failover`).

- **What happens:**
  - The head comes from the active endpoint only. A low head is `Ok`, so the validator never rotates and never warns.
  - With 3 endpoints, each bad one still stops about 1/n of the fleet.
- **Status:** CONFIRMED.
- **Fix:** take the majority or median head across endpoints, or rotate when the active one trails by K blocks; warn on N idle ticks.

### M7-9 — One endpoint can trigger a persisted `DUPLICATED_NONCE` pause with a duplicated log
`provider.rs` `log_set`/`tally` (set comparison) vs `main.rs:574-643`.

- **What happens:** a duplicated genuine log still produces the same *set* as the honest peers, so the verdict is Agreed. The second copy then pauses the scanner persistently.
- **Status:** CONFIRMED.
- **Fix:** compare multisets, or treat a duplicate `(block, logIndex)` as a disagreement; dedupe before processing.

### M7-10 — M-5 is incomplete: a half-empty allowlist passes `require = true`
`bridge-core/src/allow.rs:216-226, 320-350`.

- **What happens:** `tokens=[]` with the pinned chains switches the token check off, and vice versa. This matters because M7-1's last line of defence is the token pin.
- **Status:** CONFIRMED.
- **Fix:** under `required()`, refuse when either dimension is empty.

### M7-11 — The shared Sign token means one shared sig-store rate-limit bucket
`sig-store/src/main.rs:257-261`, `ratelimit.rs:217`.

- **What happens:**
  - One token holder sending 50+ req/s puts every validator's upsert on 429, which fails their batches.
  - A catch-up of more than about 50/N `Sent` events per window may also livelock honestly, because each retry replays the whole batch. This part is PLAUSIBLE.
- **Fix:** per-validator tokens, and keep in-batch progress across retries.

### M7-12 — Dust transfers drain the keeper and relayer gas wallets (PLAUSIBLE, design)
`Gate.sol:1070` (only `amount != 0`).

- **What happens:**
  - A 1-unit send from a cheap chain makes the keeper pay a full claim at L1 prices, plus up to 32 KiB of `autoParams` calldata.
  - EVM→Solana also pays non-reclaimable `executed` rent.
- **Fix:** a per-corridor minimum or fee, an on-chain `autoParams` cap (see H7-2), and a keeper budget.

## LOW

### Contracts

- **L7-1** `Gate.sol:674,704` — the `upgradeToAndCall` init data is not covered by the timelock. Pin `keccak256(data)` with the codehash.
- **L7-2** `bridge-core/src/submission.rs:79-81` — `decode_auto_params(..).ok().flatten()` swallows errors. It fails closed today, but a decoder divergence would let one `send` pause every validator. Fix: propagate the error and skip the event. No divergence was found.
- **L7-9** `rotate-keys.sh:61-64` does not hand over the SwapRouters, which still have an instant `setRemoteRouter` on the hot key. The UI does not check `remoteRouter` against the registry's router. This is an incomplete T-5.

### Solana gate

- **L7-3** `solana-gate/src/lib.rs:525-549` — `Config::store` leaves stale bytes after a shrink, such as a validator removal. The next appended field reads garbage, and a `bool` would brick `load_config`. Fix: `data[needed..].fill(0)`.
- **L7-4** — The 1232-byte packet limit allows at most 9 signatures per claim. The relayer sends `validators.len()` signatures rather than `threshold`, so a set of 10 or more makes every Solana claim, cancel and refund oversize. Fix: truncate to threshold and cap the threshold at 9 or less.

### Indexer, keeper and relayer

- **L7-5** The M-7 indexer fix is not enough behind a load-balanced RPC: head and logs can come from different nodes.
- **L7-6** The keeper's fee-bump memo is in-memory. After a restart, an underpriced head-of-queue nonce is never bumped.
- **L7-7** The Solana refund attester (`solana-relayer/src/refund.rs:295-360`) never received the round-5 rebind-before-routing check and recovered-address dedupe.
- **L7-8** The observer's `marker_tx` can be spoofed (history display only).

### Validator

- **L7-10** Duplicate `rpcs` entries are not deduplicated, despite the docs. `["A","A"]` makes corroboration compare an endpoint with itself.
- **L7-11** The Solana destination scale read (`scale.rs:316-390`) is single-source. One `null` answer gives `Unknown`, and the signature is withheld for good. The body is read in full before the size check.
- **L7-12** On the refund cancel leg, one endpoint answering `None` or a low head blocks all cancel attestations. It fails safe, but contradicts "one liar is outvoted".
- **L7-13** Startup waits for two healthy endpoints on *every* destination. One dead peer endpoint stops signing for the whole source chain or the whole refund loop.
- **L7-14** The delivering solana-relayer holds both the Sign and Indexer tokens, so it can recreate the M-4 pre-poison from one container.

### API

- **L7-15** The Solana API quote checks staleness against the host clock, not chain time.

## Recommended order

1. **H7-1** — operational and live. Rescope the mesh11 mounts now, and treat the mesh11 validator and price-keeper keys as exposed if the API was ever reachable.
2. **H7-2 + H7-6 + the common root cause.** One `send` stops a chain. Add the on-chain `autoParams` cap, and make every scanner quarantine permanent store rejections instead of retrying.
3. **H7-3 / H7-5 / M7-11.** Validator-set-aware sig-store with per-validator tokens. This closes three findings at once.
4. **H7-4 / M7-2.** Router refund forwarding and per-id stable accounting. This needs a router redeploy.
5. **M7-1 + M7-10** — timelocked `setGuardian`, decoded schedule events, and both allowlist dimensions required.
6. The remaining MEDIUMs, then the LOWs.
